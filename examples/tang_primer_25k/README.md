# Tang Primer 25K (GW5A-25) example — DisplayPort TX over the MIPI D-PHY

Example board top for `dp_transmitter` on the Sipeed **Tang Primer 25K**
(Gowin **GW5A-LV25MG121**, "GW5A-25"). This part has **no SERDES/GTR
transceivers**, so instead of the SERDES backend used by the Tang Mega
examples it drives DisplayPort over the GW5A's **hardened MIPI D-PHY used as
a raw NRZ serializer**. The whole `dp_transmitter` link layer (training,
scrambler, 8b/10b, MSA, audio SDPs, AUX) is reused unchanged;
`src/gowin/transceiver_bank_dphy.v` replaces the SERDES bank at the bottom of
the stack. The design rationale, silicon facts and analog chain are in
[DESIGN.md](DESIGN.md).

**Status: hardware-proven.** This path is the DisplayPort output of the
[a2fpga project](https://github.com/a2fpga/a2fpga_core)'s a2p25 board —
4-lane RBR 1080p60 with audio, through an SN75DP130 redriver into USB-C DP
Alt Mode. The gearbox and PHY bank are additionally gated by the Icarus
testbenches in `../../test_benches/` (`test_dp_dphy_tx`,
`test_transceiver_bank_dphy`).

## Why the D-PHY, in one paragraph

DP RBR is 1.62 Gbps/lane. The GW5A's hardened MIPI D-PHY TX is
protocol-free: the `MIPI_DPHY` primitive is an 8:1/16:1 gearbox serializer
plus pad drivers, and *every* bit on the wire comes from the fabric. Hold
the HS-transmit and lane enables high and it emits a continuous, arbitrary
NRZ bitstream at up to 2.5 Gbps/lane — comfortably above RBR (HBR's
2.7 Gbps is out of spec and not supported). So the FPGA transmits native DP
RBR and the only external parts are signal conditioning (AC coupling + a
redriver), not a protocol bridge. See [DESIGN.md](DESIGN.md).

## Configurations

| Build (`.gprj`)                | Lanes | Resolution | Pixel clk | Sink requirement |
|--------------------------------|:-----:|------------|-----------|------------------|
| `tang_primer_25k_720p.gprj`    | 2     | 1280x720p60  | 74.25 MHz | any DP sink (2-lane hubs included) |
| `tang_primer_25k_1080p.gprj`   | 4     | 1920x1080p60 | 148.5 MHz | a 4-lane path (pin assignment C/E + a 4-lane or native-DP sink) |

720p RBR x2 is the default (widest compatibility). 1080p60 needs the
bandwidth of **four** lanes because the D-PHY cannot reach HBR; the config
is selected purely by the `DP_TP25K_1080P` define in `gowin_defines_1080p.v`
(the top, constraints and the core's lane striping follow from it).

## Building

```
cd examples/tang_primer_25k
echo 'open_project tang_primer_25k_720p.gprj
set_option -verilog_std sysv2017
set_option -bit_security 0
set_option -use_sspi_as_gpio 1
set_option -use_cpu_as_gpio 1
set_option -use_i2c_as_gpio 1
run all
exit' | /Applications/GowinIDE.app/Contents/Resources/Gowin_EDA/IDE/bin/gw_sh
```

Three options are mandatory for a clean `gw_sh` build (in the GUI they are under
Project > Configuration):

- `-verilog_std sysv2017` — the core is SystemVerilog (`dp_transmitter.sv` and
  others); Synthesize > Verilog Language = System Verilog 2017.
- `-bit_security 0` — GW5A projects generally require it.
- `-use_sspi_as_gpio 1 -use_cpu_as_gpio 1 -use_i2c_as_gpio 1` — the SOM's 50 MHz
  oscillator sits on a dual-purpose SSPI/CPU pin (E2) and the example routes HPD
  onto a dual-purpose I2C pin (B2); these release them as regular I/O (GUI: Dual-
  Purpose Pin). Adjust to match your own `.cst` pin choices.

Unlike the Tang Mega example (which ships a `synth_check_top` because its SERDES
IP must be generated by the user first), this example includes the generated
D-PHY IP, so the `.gprj` places and routes the real `top_tang_primer_25k`.

**Verified (Gowin V1.9.12, GW5A-LV25MG121):** both projects place, route, and
generate a bitstream with timing closed — **0 setup / 0 hold violated
endpoints**. Utilization: 720p×2 = 43% CLS (5303 LUT/ALU, 4794 FF), 6/56 BSRAM;
1080p×4 = 46% CLS (5650 LUT/ALU, 5236 FF), 11/56 BSRAM — leaving roughly half the
GW5A-25 for the system the transmitter is embedded in.

## MIPI D-PHY IP generation (Gowin EDA IP Core Generator)

The generated IP is checked in under `src/mipi_dphy/` and is specific to the
GW5A-25 at RBR; regenerate it for another GW5A part or rate. Generate the
**`MIPI_DPHY`** IP (module `Gowin_MIPI_DPHY`) — **not** "MIPI TX Advance",
which is the higher-level protocol wrapper. Settings:

- **16-bit mode**, **TX ENABLE** (this part has TX), data lanes 0–3,
  **clock lane off** (DP has an embedded clock)
- Data rate **1620** Mbps, **Include PLL**, CLKIN **54.000** MHz, mDRP 50
- `Calculate` must yield **VCO = 810 MHz** (VCO must be an integer multiple
  of CLKIN; 54 x 15 = 810). The PLL makes the four serializer phases on
  clkout0–3 and, on CLKOUT4 (divider 10), a spare **81 MHz** link-symbol
  clock.
- After generation, check the RTL: the fabric bytes must wire straight to
  `DxLN_HSTXD` with nothing in between.

> **Note:** the generated `PLL_INIT` wrapper leaves the PLL `lock` signal
> dangling (not exposed on the IP's top port list), so
> `transceiver_bank_dphy` sequences the HS-enable on settle timers rather
> than on PLL lock. Re-expose `lock` at bring-up if you want to gate on it.

Two fabric PLLs sit beside the D-PHY IP:

- `src/mipi_dphy/gowin_pll/` — a generated `Gowin_PLL` that produces the
  **54 MHz** D-PHY reference from the 50 MHz oscillator (regenerate for a
  different reference crystal).
- `gowin_mgmt_pll` / `gowin_pixel_pll` — the hand-written PLLA wrappers in
  the shared `../../src/gowin/gowin_plls.v`. The management PLL makes the
  100 MHz AUX clock; the pixel PLL is instantiated *inside* `dp_transmitter`
  and makes the pixel clock from the 81 MHz symbol clock (81 x 11 / 12 =
  74.25 MHz at 720p, / 6 = 148.5 MHz at 1080p; VCO 891).

## Clocking summary

| Clock   | Freq        | Source                                            |
|---------|-------------|---------------------------------------------------|
| clk50   | 50 MHz      | SOM oscillator                                    |
| clk100  | 100 MHz     | `gowin_mgmt_pll` (AUX/management)                 |
| clk54   | 54 MHz      | `Gowin_PLL` -> D-PHY TX PLL reference             |
| clk_sym | 81 MHz      | D-PHY PLL CLKOUT4 (link-symbol clock)             |
| clk_tx  | 101.25 MHz  | D-PHY `TX_CLK_O` (16-bit gearbox byte clock)      |
| clk_pix | 74.25/148.5 | `gowin_pixel_pll` from clk_sym (DP sync clocking) |

No extra oscillator is needed — the D-PHY TX PLL does all high-speed
multiplication from the 54 MHz reference. Never inject a fabric-synthesized
high-speed clock.

## The external analog chain

The D-PHY pads emit MIPI SLVS levels (~280–540 mVpp differential), which is
roughly DP swing level 0 with no headroom to honor a sink's swing/
pre-emphasis requests during training. A **redriver that regenerates** the
link (e.g. TI **SN75DP130**, DP 1.1a/1.2, 4-lane) is therefore recommended
rather than a linear redriver: it restores the full DP VOD/pre-emphasis
level set independent of input amplitude, and its input squelch gives
correct "dead link before training" semantics for free.

```
GW5A-25 D-PHY M0 quad --(AC caps)--> SN75DP130 --(AC caps)--> connector / mux
AUX: FPGA LVDS25 pair + bias network --> (through the redriver's AUX pass) --> sink
HPD: a level into dp_hpd (in USB-C Alt Mode, reconstructed from PD by an MCU)
```

AUX never touches the D-PHY — only the main link moves to it. The AUX front
end is `src/dp_aux_pad.sv` (a true-LVDS pad cell with the hardware-proven
bias/park behavior); route it through the redriver's AUX pass-through to keep
the redriver's training auto-response available. Full detail, BOM notes and
the lane/polarity routing rules are in [DESIGN.md](DESIGN.md).

## USB-C output

The connector topology (USB-C DP Alt Mode vs a native DP receptacle), the
FUSB302B/ESP32-S3 PD + Alt Mode policy, and the TUSB1046A/TUSB546A mux are
covered by the shared [`../../usb-c/`](../../usb-c/) port specification; the
D-PHY source replaces the SERDES source upstream of the AC caps without
changing any of it. The one piece the D-PHY chain adds that the SERDES boards
do not have is the **SN75DP130 redriver** between the FPGA and the mux (see
[DESIGN.md §5](DESIGN.md), "Why a regenerating redriver"):

```
 FPGA D-PHY M0 quad ==AC==> +-----------+ ==AC==> +-------------------+
 (4 lanes, SLVS ~0.4 Vpp)   | SN75DP130 |         |                   |==> USB-C SS pairs
                            | redriver  |         |  TUSB546A-DCI     |    (all four)
 FPGA AUX (LVDS25 pair) ===> | (VOD/PE   |  AUX    |  (mux + linear EQ)|==> SBU1/SBU2
       + bias network        |  regen)   | <=pass=>|                   |
                            +-----------+         +-------------------+
                             ^ I2C (DP130 levels)   ^ I2C (DP en/flip/EQ)
                             |                       |
 FPGA HPD (dp_hpd) <-- ESP32-S3 <--I2C/INT--> FUSB302B <--> CC1/CC2
 (reconstructed from PD VDMs)   |   |
                                |   +--> VBUS 5 V source switch (TPS2553,
                                |        hardware current limit)
 MCU USB 2.0 D+/D- -------------+--- ESD --> D+/D- (pin assignment C keeps USB 2.0)
```

The D-PHY pads emit MIPI SLVS levels (~0.4 Vpp), so the **regenerating**
SN75DP130 restores the full DP swing/pre-emphasis set and answers link-training
requests; AUX is routed *through* its pass-through so its training auto-mode
stays available. On the SERDES boards the transceiver drives DP levels directly,
so there is no redriver — otherwise the mux/PD/HPD stack is identical. For a
native full-size DP jack instead of USB-C, the chain ends at DP130 -> jack and
the mux/PD stack drops out (DESIGN.md §5).
